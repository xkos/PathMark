# 本地阅读收藏夹浏览器插件——第一版需求文档

- 文档版本：1.0
- 产品范围：Chrome、Microsoft Edge 扩展
- 数据范围：完全本地，不提供账号、云同步或服务端
- 配套数据定义：[data-model.md](../models/data-model.md)
- 导出格式：[bookmark-library-export.schema.json](../schemas/bookmark-library-export.schema.json)

## 1. 产品概述

### 1.1 问题

用户在查询资料时会积累大量网页和论文链接，但现有浏览器收藏夹难以回答：

1. 哪些资料尚未阅读，哪些已经读过；
2. 当时为什么收藏，资料有什么价值；
3. 同一站点更换域名、镜像地址或统一路径前缀后，新地址是否对应曾收藏或读过的资料；
4. 如何快速按站点、标签、状态或关键词重新找到资料；
5. 如何备份并迁移全部本地数据。

### 1.2 产品目标

第一版提供一个本地优先的分类阅读收藏库：

- 一键保存当前页面并补充说明、标签和阅读状态；
- 将“站点身份”与会变化的 URL Endpoint 分离；
- 在域名或路径前缀变化后，仍能识别同一份资料；
- 记录未读、阅读中、已读和归档信息；
- 支持分类、标签、搜索、筛选、编辑、删除和批量整理；
- 支持完整 JSON 导入和导出。

### 1.3 非目标

第一版不包含：

- 用户账号、服务端、跨设备自动同步；
- 团队共享、公开收藏列表和协作批注；
- 自动抓取或永久保存网页正文；
- AI 摘要、向量搜索或内容推荐；
- 自动发现网站新域名；
- 自动探测所有 Endpoint 的可用性；
- Firefox、Safari 或移动端应用；
- 与浏览器原生收藏夹的双向实时同步。

## 2. 核心原则

### 2.1 地址不是资料身份

完整 URL 只表示一次访问地址。属于同一站点的多个 Endpoint 可以映射到相同资源键，收藏条目的稳定身份由 `siteId + resourceKey` 决定。

### 2.2 已读记录默认保留

标记为已读不会删除条目。用户可将其归档，使其退出默认工作列表，同时继续支持“这个页面是否看过”的判断。彻底删除必须是独立操作。

### 2.3 阅读与归档相互独立

阅读状态是“未读 / 阅读中 / 已读”；归档是另一个布尔状态。归档未读资料不会自动改成已读。

阅读状态表示当前阅读任务，曾读记录表示历史事实。资料从已读重新标为未读时，当前已读时间可以清空，但首次已读时间必须保留，以继续回答“以前是否读过”。

### 2.4 可解释、可修正

保存或匹配时，界面应能说明命中的站点、Endpoint 和资源键。用户可以更换所属站点或编辑匹配配置，不依赖不可见的黑盒判断。

### 2.5 来源与分类相互独立

站点回答“内容来自哪里”，收藏分类回答“我把资料放在哪里”。一个分类可以包含多个站点的条目，一个站点的条目也可以分布在多个分类中。标签用于跨分类的多维标记，不能替代主分类。

## 3. 用户与主要场景

第一版只有一个本地使用者，不建立用户实体。

### 场景 A：保存待阅读资料

用户打开论文或网页，点击扩展按钮，确认自动读取的标题与地址，选择收藏分类，填写说明和标签，保存为未读。

### 场景 B：判断是否已经看过

用户打开一个页面，扩展图标或弹窗显示该页面是否已收藏、当前阅读状态、首次收藏时间和最近阅读时间。

### 场景 C：站点更换域名

旧地址为 `https://old.example.com/docs/paper/123`，新地址为 `https://new.example.org/archive/paper/123`。用户把两个前缀配置到同一个站点后，两者都映射为 `/paper/123`，并被识别为同一条目。

### 场景 D：整理积压内容

用户在管理页按收藏分类或站点筛选未读资料，按收藏时间排序，批量移动分类、添加标签、归档或删除。

### 场景 E：迁移或备份

用户导出一个包含收藏分类、站点、Endpoint、收藏条目和设置的 JSON 文件；之后可通过合并或替换模式导入。

## 4. 信息架构

扩展包含三个入口：

1. **弹窗（Popup）**：识别当前页面、快速保存、查看或修改当前条目状态；
2. **侧边栏（Side Panel）**：浏览过程中查看当前站点及相关收藏，可作为增强入口；若浏览器环境不支持，核心能力仍可由弹窗和管理页完成；
3. **管理页（Options / Library）**：完整搜索、筛选、编辑、批量操作、站点配置和导入导出。

默认导航分为：

- 收件箱：尚未选择收藏分类的条目；
- 未读：未归档且阅读状态为未读或阅读中；
- 已读：阅读状态为已读且未归档；
- 归档：所有已归档条目；
- 分类：按用户建立的可嵌套分类查看条目；
- 站点：按站点查看条目并配置 Endpoint；
- 标签：按标签聚合；
- 设置：规范化规则、导入、导出和本地数据管理。

## 5. 功能需求

### FR-01 保存当前页面（P0）

1. 从当前活动标签页读取标题和完整 URL；
2. 默认阅读状态为未读，默认不归档；
3. 用户可编辑标题、说明、收藏分类和标签；
4. 系统尝试匹配已有站点 Endpoint；
5. 未匹配时允许保存为未归站条目，或由用户选择/新建站点；
6. 保存前展示最终命中的站点和资源键；
7. 若规范键已存在，不创建静默重复项，而是打开已有条目供用户更新。

验收标准：保存后关闭并重新打开浏览器，条目仍存在；再次访问等价地址时能显示已有条目。

### FR-02 编辑与状态管理（P0）

用户可以编辑：

- 标题；
- 个人说明；
- 收藏分类；
- 标签；
- 所属站点；
- 阅读状态：未读、阅读中、已读；
- 是否归档。

状态规则：

- 首次切换为已读时同时记录永久保留的 `firstReadAt` 和当前 `readAt`；
- 之后再次切换为已读时更新 `readAt`，但不覆盖 `firstReadAt`；
- 从已读切回其他状态时清空 `readAt`；
- 从已读切回其他状态时保留 `firstReadAt`；
- 打开条目时更新 `lastOpenedAt` 和 `openCount`；
- 归档不改变阅读状态；
- 删除需要确认，删除后不再用于已读判断。

### FR-03 收藏分类管理（P0）

用户可以：

- 新建、重命名、排序和删除收藏分类；
- 建立父子分类，第一版最多支持 5 层；
- 将条目移动到某个分类或移回收件箱；
- 在分类树中查看包含的条目数和未读数；
- 删除分类时选择“条目移入收件箱”或“同时删除条目”，并明确显示影响数量。

约束：

- 同一父分类下名称按大小写不敏感唯一；
- 分类不得把自身或后代设为父分类；
- 删除父分类时默认连同子分类结构一起删除，但其中条目默认移入收件箱；
- 收藏分类不参与 URL 身份判断，移动分类不会改变 `canonicalKey`。

### FR-04 站点与 Endpoint 管理（P0）

用户可以：

- 新建、重命名和删除站点；
- 为站点添加、编辑、排序、启用或停用多个 Endpoint；
- 设置 Endpoint 的协议、主机、可选端口和路径前缀；
- 预览某个 URL 将匹配哪个 Endpoint，以及生成的资源键；
- 将未归站条目或其他站点的条目迁入该站点并重新计算规范键。

约束：

- Endpoint 必须是合法的 `http` 或 `https` URL 前缀；
- Endpoint 不得包含用户名、密码、查询参数或片段；
- 完全相同的规范化 Endpoint 不能属于多个站点；
- Endpoint 路径按完整路径段匹配，`/docs` 不得匹配 `/docs2`；
- 多个 Endpoint 同时匹配时，选择路径前缀最长者；同长度冲突必须由用户修正，不能随机选择；
- 删除仍有关联条目的站点时，必须选择“条目变为未归站”或同时删除条目。

### FR-05 URL 规范化与身份识别（P0）

处理流程：

1. 只接受 `http` 和 `https` 页面；
2. 将主机名转为小写，移除默认端口；
3. 丢弃 URL 片段 `#fragment`；
4. 保留路径大小写，不自动解码具有语义差异的字符；
5. 将尾部 `/` 按设置统一处理，默认除根路径外移除；
6. 移除全局和站点配置的忽略查询参数；
7. 对保留的查询参数按键和值稳定排序；
8. 查找匹配的 Endpoint；
9. 已归站条目生成 `resourceKey`，再由 `siteId + resourceKey` 生成 `canonicalKey`；
10. 未归站条目使用规范化完整 URL 生成 `canonicalKey`。

默认忽略的查询参数包括大小写不敏感的 `utm_*`、`fbclid`、`gclid`、`mc_cid`、`mc_eid`。用户可以修改全局规则，并可在站点级覆盖。

站点可配置查询参数策略：

- `keep-all-except-ignored`：保留除忽略列表外的所有参数，默认策略；
- `keep-only-identity`：只保留明确配置的身份参数，适合 `/view?id=123` 一类站点。

### FR-06 当前页面识别（P0）

弹窗应展示：

- 是否已收藏；
- 是否曾读过及当前阅读状态；
- 首次已读时间；
- 是否归档；
- 所属站点；
- 当前 URL 命中的 Endpoint；
- 首次收藏、最后更新和最近打开时间；
- 若当前地址与原始地址不同，明确提示“通过同站点资源键匹配”。

### FR-07 地址解析与打开（P0）

1. 每个站点的 Endpoint 有用户可调整的优先级；
2. 打开条目时，默认用最高优先级的已启用 Endpoint 拼接资源键的路径与查询参数；
3. 用户可从菜单选择其他 Endpoint 打开；
4. 原始地址始终保留，可显式选择打开；
5. 第一版不承诺后台检测 Endpoint 是否可访问，也不因网络错误自动修改数据。

### FR-08 搜索、筛选与排序（P0）

搜索范围：标题、说明、原始 URL、资源键、站点名称和标签。

筛选条件：

- 阅读状态；
- 是否归档；
- 收藏分类或收件箱；
- 站点或未归站；
- 一个或多个标签；
- 收藏时间和已读时间范围。

排序方式：收藏时间、更新时间、最近打开时间、标题；均支持升序和降序。

### FR-09 批量操作（P1）

管理页支持对选中条目批量：

- 修改阅读状态；
- 归档或取消归档；
- 添加或移除标签；
- 移动到收藏分类或收件箱；
- 移动到站点；
- 删除。

移动站点时若产生规范键冲突，必须展示冲突并让用户逐项或按统一规则处理。

### FR-10 JSON 导出（P0）

1. 导出文件包含格式版本、导出时间、应用信息、设置、收藏分类、站点和全部条目；
2. 默认包含已归档条目，不包含运行时缓存或临时 UI 状态；
3. 文件为 UTF-8 编码的可读 JSON；
4. 文件名建议为 `reading-bookmarks-YYYY-MM-DD.json`；
5. 导出不会删除或修改本地数据；
6. 导出前展示分类数、站点数、条目数和归档条目数。

### FR-11 JSON 导入（P0）

支持两种模式：

- **合并**：保留现有数据，导入新数据并处理冲突；
- **替换**：校验成功并经二次确认后，用导入内容替换全部本地业务数据。

导入必须分为“校验预览”和“确认写入”两步。预览展示：格式版本、分类数、站点数、条目数、新增数、更新数、跳过数、冲突数和错误列表。

合并规则：

1. 先按 `id` 匹配同一实体；
2. 不同 ID 但站点 Endpoint 完全相同时，报告站点冲突，不自动合并站点；
3. 不同 ID 但条目 `canonicalKey` 相同时，报告条目冲突；
4. 对同 ID 实体，默认保留 `updatedAt` 较新的版本，但在写入前允许改选；
5. 不同 ID 但位于同一父分类且名称相同的分类，报告分类冲突；
6. 引用不存在站点或分类的条目属于校验错误；
7. 未知字段可以忽略并保留兼容性，缺少必填字段则拒绝对应记录；
8. 不支持的主格式版本必须拒绝整份导入。

写入要求：导入应以事务方式执行；任何非预期写入错误都不得留下半份数据。

### FR-12 本地数据与隐私（P0）

1. 所有业务数据仅写入浏览器扩展的本地存储；
2. 卸载扩展可能导致本地数据被浏览器删除，设置页必须提示定期导出备份；
3. 不向第三方发送 URL、标题、说明、标签或使用统计；
4. 不申请实现核心功能以外的站点访问权限；
5. 清空全部数据必须二次确认，并建议先导出备份。

## 6. 数据一致性规则

1. `Collection.id`、`Site.id` 和 `Item.id` 在各自实体集中唯一；
2. 同一站点内不能存在相同的规范化 Endpoint；
3. 全库不能有两个条目共享同一个 `canonicalKey`；
4. 条目的非空 `collectionId` 必须引用存在的收藏分类，分类的非空 `parentId` 必须引用存在分类且不能形成环；
5. 已归站条目的 `siteId` 必须引用存在的站点；
6. 已归站条目必须有 `resourceKey`，未归站条目不得伪造 `siteId`；
7. `originalUrl` 永远保留首次收藏地址，后续打开地址记录在 `lastResolvedUrl`；
8. `createdAt <= updatedAt`；若存在 `readAt`，阅读状态必须为已读；
9. 修改 Endpoint 时必须预演匹配范围和解析地址变化，但不得自动重算现有条目的 `resourceKey` 或 `canonicalKey`；
10. 只有迁移 Site 或用户显式执行身份重映射时才重算资源键；重算导致规范键冲突时禁止静默覆盖；
11. `firstReadAt` 一旦写入不得因阅读状态回退而清空；`readAt` 非空时 `firstReadAt` 必须非空且不晚于 `readAt`。

## 7. 非功能需求

### 性能

- 10,000 条收藏规模下，管理页首次展示目标不超过 2 秒；
- 常用筛选、当前页面匹配和保存操作目标不超过 200 毫秒，不含浏览器页面加载；
- 搜索输入采用增量或防抖执行，不能明显阻塞界面。

### 可靠性

- 所有多实体写入使用本地数据库事务；
- 数据结构升级前创建可恢复的迁移路径；
- 导入前完成全量校验，替换导入失败时保留原数据。

### 可用性

- 保存当前页面应在三次以内交互完成；
- 颜色不能是阅读状态的唯一表达；
- 键盘可以完成搜索、保存和状态切换等核心操作；
- 危险操作必须说明影响对象数量。

## 8. 第一版优先级与发布边界

### P0：首发必须具备

- 保存、编辑、删除收藏条目；
- 可嵌套收藏分类与收件箱；
- 阅读状态与独立归档状态；
- 站点及多 Endpoint 管理；
- URL 规范化、重复识别、当前页面识别；
- 使用不同 Endpoint 解析并打开条目；
- 搜索、筛选、排序；
- 本地持久化；
- JSON 校验预览、合并导入、替换导入和完整导出；
- 数据库升级与导入失败回滚。

### P1：可随第一版迭代

- 侧边栏；
- 批量操作；
- 快捷键；
- 从浏览器原生书签单向导入；
- Endpoint 配置变更的批量影响预览增强。

## 9. 发布验收场景

1. 保存一个未读页面，重启浏览器后仍能检索并打开；
2. 同一 URL 去掉追踪参数后再次保存，不产生重复条目；
3. 给站点添加新域名与路径前缀后，新旧 URL 都命中同一个条目；
4. `/docs` Endpoint 不错误匹配 `/docs2/page`；
5. `/view?id=1` 与 `/view?id=2` 在身份参数配置下被识别为不同条目；
6. 将条目标记已读后归档，当前页面仍显示“已读”；
7. 将已读条目改回未读，`readAt` 被清空；
8. 导出后清空本地数据，再以替换模式导入，分类、站点、Endpoint、条目和设置一致恢复；
9. 合并导入存在重复规范键的数据，系统展示冲突且不静默覆盖；
10. 导入格式错误或写入中断时，原数据库保持完整；
11. 显式执行身份重映射导致两个条目规范键相同时，提交被阻止并展示冲突；
12. 10,000 条测试数据下满足核心性能目标；
13. 把条目从分类 A 移到分类 B 后，当前页面识别结果不变，且分类筛选结果正确更新；
14. 删除含有子分类的分类后，按用户选择将其中条目移入收件箱，且不存在悬空 `collectionId`。
15. 已读条目重新标为未读后，当前 `readAt` 被清空，但 `firstReadAt` 保留且页面仍显示“曾读过”。
